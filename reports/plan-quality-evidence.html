Headline · reproduced in two independent runs

The operator-only baseline picked an operator the chip cannot execute

On fft-iclib, the CheckMate + 10 arm selected T24 Magnitude-Only FFT. T24 is registered requires_fpu = true. The MSP430FR5994 has no floating-point unit. The same arm then failed to implement T24 at all — so the plan was both infeasible and untrue.

CHAI's gatekeeper had already removed T24 from the menu before the model saw it. Same catalogue, same model, same benchmark — the control plane is the only difference.

Coverage · the first thing to look at

On five of six benchmarks, no arm produced a usable plan

72 cells ran to completion. Only 16 yielded an accepted plan at all. That is a statement about the 7B planner, not about the framework around it — every rejection below was verified as correct, not over-strict.

The Sobel failure is worth reading twice. The prompt was changed to forbid floating-point loop bounds and to require an integer percentage knob; the model wrote y_size1 * 0.8 anyway and declared iteration_pct without ever using it. The behavioural check caught it because the knob moved nothing.

Failure mode · caught behaviourally

A knob that changes nothing

This passed the original checker: it contains a return and an early-exit-looking identifier. But max_iterations is folded into limit, and limit is never read. The loop condition is untouched. Setting the knob to any value produces identical output.

  • Static check — a pattern match; each gap is patched by another pattern.
  • Behavioural check — drive the knob to the far end of its range, rebuild, re-run. No change in output means no operator, whatever the code is named.
// accepted, declared T21 Early-Exit
static uint16_t sqrt16(uint32_t x) {
  /*Knob Variables Declaration Start*/
  int max_iterations = 50;
  /*Knob Variables Declaration End*/

  uint16_t hi = 0xffff, lo = 0, mid;
  uint32_t s = 0;

  int limit = (max_iterations * 100) / 100;
  // ^ computed, then never read again

  while (s != x && hi - lo > 1) {
    // ^ knob absent from the condition
    mid = ((uint32_t)hi + lo) >> 1;
    s = (uint32_t)mid * mid;
    if (s < x) lo = mid; else hi = mid;
  }
  return mid;  // ordinary return
}
Scope

What this does not yet show

  • No performance win. On both benchmarks measured, every arm that produced a configuration landed on the identity point — error 0, 19/19 power cycles, objective 1.0. Neither CHAI nor the baselines beat the unapproximated program.
  • Coverage, not quality, is the binding constraint. Only 16 of 72 cells produced a plan at all, and only ar-iclib has data in every arm. Five benchmarks contribute nothing to the comparison.
  • Fewer plans, not demonstrably better ones. CHAI accepted about half as many plans as the baselines. Stricter gates reject more; whether the survivors run better is what the objective decides, and it has not yet.
  • The FPU finding is a mechanism demonstration — one operator, one benchmark, reproduced twice. It shows the gate works, not how often it matters.
  • On fft-iclib no arm produced a usable plan at all in the latest run. The rejections are correct, not over-strict: declared identity settings measured 78% error, and several candidates did not compile. At this model size FFT is limited by the planner, not by the framework around it.
