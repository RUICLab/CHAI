Mechanism

Why the enforced artifacts ship zero

Four gates, in the order a candidate meets them. Each rejects a specific, independently checkable defect and hands the model a reason to repair.

1
Feasibility gate — before the model is prompted

Operators the chip cannot run are removed from the menu. On fft-iclib that is 16 of 32, including T24 Magnitude-Only FFT, which requires an FPU the MSP430 does not have. The unenforced arm selected T24 anyway.

2
Per-function narrowing

Each function gets its own menu instead of one app-wide list: 1 distinct menu in the baselines against 7 in the enforced arms. A tiny accessor is offered nothing; the feature extractor is offered four operators.

3
Plan contract

The plan must name a region that exists, a knob with a reachable identity value, and an invariant. Free prose cannot be checked against code later; a structured record can.

4
Behavioural verification

Each knob is driven to the far end of its range, rebuilt and re-run. If the output does not move, the operator is not implemented — whatever the code is named. This is what a static pattern match kept missing.

Scope

What this does not show

  • Nothing about speed. No arm has beaten the unapproximated program on any benchmark measured. This sweep skipped search and simulation entirely.
  • Coverage is thin. Only ar-iclib has data in all four arms; the pooled rate leans on it.
  • CHAI accepts fewer plans — 13 and 12 against 26 and 20. Stricter gates reject more, which is why the chart is a rate and not a count.
  • Unsupported labels shipped is a lower bound. A checker can show an operator is absent; it cannot prove one is present.
  • The zero is partly definitional. CHAI prunes disproven labels before writing accepted artifacts. These runs did not record raw pre-pruning label errors; fresh runs do.
